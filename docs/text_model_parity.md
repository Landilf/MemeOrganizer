# Проверка текстовой модели v0.2.0-mobile

Пакет `meme-organizer-text-champion-v0.2.0.tar.gz` содержит INT8 ONNX-модель, токенизатор и `smoke_test_pack.json`. SHA-256 модели: `d9eb7199f4a4870987f5c40a3259538278f5765d3e390a0d38f1636d1b230abc`.

На Android-устройстве ARM64 проверены все восемь примеров из пакета: `input_ids` и `attention_mask` совпадают с эталоном. При сравнении выходов модели с `full_embedding` три примера не достигли выбранного для проверки порога cosine similarity > 0.995:

| Пример | Cosine similarity |
| --- | ---: |
| query_2 | 0.98945964 |
| passage_3 | 0.99413638 |
| passage_4 | 0.99423154 |

ONNX Runtime Android 1.20.0 и 1.22.0 дали одинаковые результаты. При отключении оптимизаций графа расхождения остались; версия 1.17.1 из README не загрузила модель с IR version 10. Порог 0.995 — выбранный нами критерий проверки, а не допуск, установленный авторами модели.

В исходном коде сборки пакета на коммите `305efce` `SmokeTestGenerator._run_single` формирует эталон, запуская экспортированную INT8-модель через `CPUExecutionProvider` по одному примеру с теми же `input_ids` и `attention_mask`; значения округляются до шести знаков. Это объясняет происхождение эталона, но не устанавливает причину расхождения на Android.

По сообщению Сани, эталон создан на Linux x86-64 (Intel Core i7-12700H), Python 3.13.14, ONNX Runtime 1.32.0; повторный запуск на этой машине совпал с `full_embedding` с максимальной абсолютной ошибкой 0.0000005. Эти результаты предоставлены Саней и самостоятельно на x86-64 не проверены.

Саня предложил для сравнения Android ARM64 с эталоном порог cosine similarity >= 0.98 и допуск на L2-норму 1.0 ± 0.0001. Тест обновлён по этим критериям; дополнительно проверяется порядок `similarity_tests` и гибридная выдача `hybrid_ranking_tests` с эталонными BM25-скорами. Последняя проверка оценивает влияние Android-векторов на ранжирование, но не проверяет реализацию BM25.

25 ноября 2026 года на подключённом Android ARM64-устройстве прошли все три проверки: точное совпадение токенизации, cosine >= 0.98 и L2-норма, а также совпадение порядка в `similarity_tests` и всех четырёх `hybrid_ranking_tests`. Время выполнения — 6.326 секунды.

Различия между ядрами INT8 на x86-64 и ARM64 — возможное объяснение расхождения, а не подтверждённая причина: версии runtime и архитектуры одновременно различаются. Успех на восьми smoke-примерах также не подтверждает качество поиска на всём датасете.
